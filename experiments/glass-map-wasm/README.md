# Displacement-map experiment

This standalone prototype compares TypeScript-equivalent JavaScript and Rust/Wasm
for one part of the glass renderer: generating a two-channel refraction field.
It is not imported by Lenso UI and does not replace browser rendering.

Both implementations include a full-field path and a quarter-field path. The
latter calculates symmetric geometry once and mirrors the signed displacement
before rounding. Mirroring encoded bytes with `255 - value` is incorrect for the
neutral value of 128. Both Wasm paths reuse their allocation; measurements include
copying the result back to JavaScript.

## Run

Use an installed Rust toolchain with the `wasm32-unknown-unknown` target. The former browser benchmark runner has been removed; the measurements below are historical.
From the repository root:

```sh
CARGO_TARGET_DIR=/tmp/lenso-glass-wasm-target cargo build --manifest-path experiments/glass-map-wasm/Cargo.toml --release --target wasm32-unknown-unknown
```

Native Rust checks are `cargo check`, `cargo test`, `cargo clippy --all-targets --all-features -- -D warnings`, and `cargo doc --no-deps`, with the same manifest path.

## Measurement and decision

2026-10-27, Apple M2 Pro, 16 GB, macOS 27.0.1. Ten warmups, nine alternating-order
rounds, ten maps per round; numbers below are median milliseconds per map.
Map density is 2×; dimensions are logical pixels. This is a local microbenchmark,
not a frame-rate or complete initialization measurement.

| Engine                 | Geometry | Full TS | Symmetric TS | Full Wasm | Symmetric Wasm |
| ---------------------- | -------- | ------: | -----------: | --------: | -------------: |
| WebKit 26.6            | 83×50    |    0.70 |         0.20 |      1.00 |           0.30 |
| WebKit 26.6            | 110×50   |    0.90 |         0.30 |      1.10 |           0.40 |
| WebKit 26.6            | 320×180  |    7.60 |         2.70 |      5.30 |           2.10 |
| WebKit 26.6            | 640×360  |   24.20 |         8.60 |     14.90 |           5.90 |
| Chromium 153.0.8010.12 | 83×50    |    0.51 |         0.21 |      0.92 |           0.31 |
| Chromium 153.0.8010.12 | 110×50   |    0.69 |         0.28 |      1.08 |           0.38 |
| Chromium 153.0.8010.12 | 320×180  |    4.65 |         1.86 |      5.32 |           2.14 |
| Chromium 153.0.8010.12 | 640×360  |   18.24 |         7.29 |     21.75 |           8.84 |

Every generated byte matches the full TS reference for these four geometries in
both engines. This does not establish parity for shine, shade, PNG encoding, or
the complete browser renderer. The Wasm binary is 42,012 bytes; local compile and
instantiate took 10ms in WebKit and 8.1ms in Chromium, excluding network transfer.

Keep the shipping interaction path in TypeScript. Pointer interaction reuses
existing maps; its expensive part is SVG painting and compositing. Even the
optimized Wasm kernel cannot execute that browser work. Symmetric TS is the
better measured first candidate for new button maps. Wasm earns a measurable
advantage over symmetric TS only for the larger WebKit fields in this sample.

If future profiles show batches of uncached large geometries dominating load,
compare a worker-based symmetric TS implementation with a worker-based Wasm
implementation, including startup, buffer transfer, shine/shade, and image
encoding. That worker experiment is not implemented here. Do not describe this
kernel as a Wasm glass renderer or infer universal speedups from these results.

The adapted Snell-law field retains its MIT license in `LICENSE.txt`.
The quarter-field optimization follows the symmetry discussion in
[Aave's implementation report](https://aave.com/design/building-glass-for-the-web).
