Every Chromium sample also verifies current-scope navigation count, unique search results, language and version counterpart links, canonical/language updates, browser Back and exactly three requested scope indexes across the tested transitions. Current builds also assert that no page module is requested for the initial pre-rendered page, even during first interaction: Exact reuses its per-page checkpoint. Only the three subsequently visited Markdown pages request body modules; Back uses synchronously cached page replies, seeded from the native kept hook for the initial page and populated when later imports resolve. Sentinel prose is absent from app.js. Sitemap entries match the route count. WebKit functionally verifies the largest 300-page fixture, including a deep link in the last scope, search, language/version changes and Back; its timings are not mixed into the Chromium table.

## Findings and limits

The initial 100-page build failed Exact's 64-level expression nesting limit. Route lookup now uses a flat name index and balanced selection, with page identity derived from that selected record. Shared navigation, groups and labels are stored once per locale/version rather than repeated in every page constructor. A diagnostic 300-page build before sharing had a 690,850-byte gzip entry; after sharing it was about 410 KB. The diagnostic timing samples ran once and are not a statistical before/after performance claim.

The site remains one application. Markdown text, raw source and syntax-token values are now emitted as page data modules. Small native block templates are shared across pages, while layout, route metadata, root resources and custom Exact/widget code stay in the application. Initial HTML contains the complete current page and its checkpoint; navigation imports only the destination page data. Cached replies return synchronously so async placeholders cannot collapse the page before native history restoration. The optional saved 300-page inline build is measured in the same browser run without rebuilding it. Build times can increase because page replies now pass through the typed resource and static-rendering pipeline; the saved baseline has no new build timing. Different structures can add templates, and custom Exact code is not split, so these results do not establish a general performance budget. Initial HTML is pre-rendered; first paint and activation have different costs. No default theme, visual parity, real-device or native-platform acceptance is claimed. Reading/custom-layout checks are recorded separately in [ACCEPTANCE.md](ACCEPTANCE.md).

Reproduce from this package with the documented EXACT_ROOT and PLAYWRIGHT_MODULE: `bun run test:scale`. Optional `SCALE_BASELINE_DIR` points to an unchanged saved 300-page output of this fixture for a same-run comparison. `SCALE_PAGES=100,200,300` selects sizes; `PERF_RUNS` sets 1–10 samples (default 3). Raw measurements and generated fixtures live in [.cache/scale/results.json](.cache/scale/results.json). Background machine work can affect local timing.
