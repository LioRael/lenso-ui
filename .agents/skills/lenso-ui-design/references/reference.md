# Read a visual reference

Record the reference URL or file, revision when known, viewport, theme,
direction and open/selected state. Capture the rendering rather than inferring
it from component names or a feature list.

Inspect these layers together:

1. **Frame:** page height, outer margins, header/footer, rails, pane widths,
   alignment, scrolling ownership and breakpoint behavior.
2. **Hierarchy:** type scale, weights, line heights, line lengths, information
   density, spacing groups and the primary focal point.
3. **Surfaces:** background/elevation hierarchy, separators, radius roles,
   shadows, accent/status color roles and focus treatment.
4. **States:** selection, menus/dialogs, empty/invalid content, loading and
   narrow-screen navigation. Distinguish initial animation from settled geometry.

For this reconstruction, the pinned HeroUI source is documented in `DESIGN.md`.
Locate the exact page/composition and its helpers, not merely individual
component demos. Preserve applicable original licenses and identify adaptations.
Translate source styling to Lenso theme variables and StyleX while preserving
native interaction ownership.

Remote HeroUI Pro screens are visual references, not proof of an available
open-source implementation or a right to redistribute assets/source. Observe
their structure when authorized; build first-party Lenso compositions and keep
the licensing/availability distinction explicit.

If browser/source access fails, report the specific missing reference and what
can still be verified. A written guess is not a reference capture.
