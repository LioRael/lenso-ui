## Usage

```tsx
import { Command } from "@lenso/primitives/command";

export function Commands({ onCreate }: { onCreate: () => void }) {
  return (
    <Command.Root>
      <Command.Input aria-label="Find a command" placeholder="Type a command…" />
      <Command.List>
        <Command.Empty>No matching commands.</Command.Empty>
        <Command.Item value="create-document" onSelect={onCreate}>
          Create document
        </Command.Item>
      </Command.List>
    </Command.Root>
  );
}
```

Command composes Base UI Autocomplete in inline, always-open mode. For a floating command palette, compose it inside a Dialog; the dialog owns visibility, focus containment and dismissal. The primitive does not install a global keyboard shortcut.

## Root API

| Prop | Type / default | Behavior |
| --- | --- | --- |
| `value`, `defaultValue` | Query string; default `""` | Controlled / initial query |
| `onValueChange` | `(value, details) => void` | Native query-change callback |
| `items` | `readonly Value[]` | Optional collection |
| `filteredItems` | `readonly Value[]` | Externally filtered collection |
| `filter` | Native filter callback or `false` | `false` disables internal filtering |
| `autoHighlight` | Native prop; default `"always"` | Highlight policy |
| `keepHighlight` | `boolean`; default `true` | Retain highlighted item |
| `readOnly` | `boolean`; default `false` | Also prevents `Item.onSelect` execution |

Other props come from `Autocomplete.Root.Props<Value>`, except `inline`, `open`, `defaultOpen`, `onOpenChange` and `mode`, which are owned by Command. Selecting an item runs its action without replacing the query with the item's label. Set the controlled query yourself when an action should clear it.

## Parts and hooks

| Export | Contract |
| --- | --- |
| `Command` / `Command.Root` | The same root component |
| `Input` | Native Autocomplete input props; preserves IME composition |
| `List` | Native result list |
| `Item` | Required `value: Value`; optional `onSelect(value): void`; native item props and div ref |
| `Empty` | Empty-result content |
| `Group`, `GroupLabel` | Grouped results and label |
| `Separator` | Result separator |
| `Collection` | Native collection rendering |
| `Status` | Native status announcements |
| `Clear` | Native query clear control |
| `Command.useFilter` / `useCommandFilter` | Native Autocomplete filtering hook |

Named `CommandRoot`, `CommandInput`, `CommandList`, `CommandItem`, `CommandEmpty`, `CommandGroup`, `CommandGroupLabel`, `CommandSeparator`, `CommandCollection`, `CommandStatus` and `CommandClear` exports are also available, with the local prop types defined in source.

## Execution and keyboard

Base UI owns highlighting and input/list keyboard interaction. Input composition events do not trigger its keyboard handler while an IME is composing. The item's native `onClick` runs before `onSelect`; preventing the event's default or Base UI handler cancels the action. `readOnly` blocks `onSelect`, but application code in `onClick` remains your responsibility.

For object values, configure native item labeling and collection props consistently. Keep command actions in `onSelect`, and give the input a label. Announce loading/errors through `Status` when results come from your own async source.
