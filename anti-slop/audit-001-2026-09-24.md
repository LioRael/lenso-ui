# Documentation site antislop audit 001

Scope: local `lenso-ui` documentation preview at `http://127.0.0.1:4173/`, with detailed inspection of `/components/command-menu`. Compared the current layout with the docs direction in `DESIGN.md`. Checked desktop, 375px and 320px mobile, dark and light themes. This is an audit, not a fix pass.

Design read: developer-facing component documentation for builders, in the Console pilot's restrained near-neutral language. ENERGY 1 / RHYTHM 2 / MOTION 1. The component example should be the focal point, while navigation and controls recede.

## Findings

1. **HIGH · R-03: Mobile header touch targets are too small.** At 375px, the menu button measures 28 × 28px, search 39 × 32px, and theme 32 × 32px. The same compact controls remain at 320px. They miss the skill's 44px tap-target requirement; the search button also breaks `DESIGN.md`'s square icon-only geometry. Give each control a 44 × 44px hit area while keeping its glyph visually compact.

2. **HIGH · R-03: The Command Menu preview clips usable content on mobile.** At 320px, the “Set due date…” command ends at viewport y=664 while the preview stage ends at y=568. Both the outer stage and inner command canvas use `overflow: hidden` with fixed heights; the last commands cannot be seen in the stage. Let the example fit or scroll inside a clearly bounded preview at narrow widths. Evidence: `apps/docs/components/docs/live-playground.stylex.ts` and `apps/docs/components/docs/playground/adapters/stage.stylex.ts`.

3. **HIGH · R-26: Example commands look actionable but have no command outcome.** Clicking “Assign to…” changes the selected item only; no assignment surface, confirmation, or explanatory feedback appears. The demo can intentionally teach selection, but then it should say so and use labels that make this behavior clear. Otherwise give the command an observable example action. Evidence: `apps/docs/components/docs/playground/adapters/overlays.tsx` renders `CommandMenu.Item` without an action handler.

4. **HIGH · R-38: The preview uses plausible but unexplained fixture content.** `TES-14 · kkk`, “Ask Lenso Tab”, and the same `S` shortcut on every command look like a real issue context while saying nothing about the component. In a live playground, label sample context as sample data and use meaningful, distinct shortcut examples, or remove the context line. Evidence: `apps/docs/components/docs/playground/adapters/overlays.tsx`.

5. **LOW · C-3 / R-31: The desktop inspector is an oversized empty card.** The Command Menu playground sets a 488px-tall inspector even though it has only three short controls. Most of the right panel is unused, adding a second visual block without a content purpose. Size the inspector to its content, or align controls in a compact row above or below the preview. Evidence: `apps/docs/components/docs/live-playground.stylex.ts` (`commandMenuInspector`).

6. **LOW · R-20 / R-31: Repeated component metadata weakens page-specific hierarchy.** “Figma canonical” appears in 17 MDX pages and “Implementation ready” in 14. On Command Menu they sit directly under a useful description but do not explain what the reader can do next. Replace generic status phrases with verifiable source links or omit them; keep metadata only where it changes a builder's decision. Evidence: `apps/docs/contents/components/command-menu/content.mdx` and the repeated frontmatter across `apps/docs/contents`.

## Observed passes and limits

- The 320px and 375px pages have no document-level horizontal overflow (`scrollWidth === innerWidth`); the problem in finding 2 is clipping inside the preview.
- Search opens, focuses its field, shows results and a no-match state, and closes with Escape. The theme toggle renders both dark and light. Navigation and the current page were visually checked.
- This pass sampled the Command Menu component page and shell. It did not click through every playground in the catalog or run the full antislop Delivery Gate, so it is not a site-wide PASS claim.

This audit made no UI edits. The owner subsequently approved findings 1–6; implementation evidence is in `follow-up-001-2026-09-24.md`.
