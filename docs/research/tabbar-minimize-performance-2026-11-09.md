# TabBar minimize performance — 2026-11-09

## Findings

The minimize spring wrote layout properties and then read the selected icon,
list and group geometry on every frame. The root ResizeObserver also measured
the expanded flex layout in response to height changes produced by that same
animation. Indicator geometry, copied labels and fitted glass optics added work
while the group was changing size.

## Changes

- Cache expanded width and selected icon offset when content, selection or root
  width changes. Spring frames only write interpolated properties. Ignore root
  height changes generated by minimization.
- Keep the documentation destination row at its expanded width throughout the
  animation, avoiding a separate button-width jump.
- Suspend indicator fitting and label-copy updates during resizing. Restore
  them once after expansion, batching immediate spring updates into one paint.
- Keep native backdrop blur and the normal action contour during resizing;
  restore fitted optics at rest. The selected destination remains visible.
- Preserve spring velocity on reversal, reduced-motion settlement and focus
  restoration when expanding.

## Local measurements

Chromium, 390 × 844 viewport, warmed documentation page, 4× CPU slowdown,
three scroll-driven collapse/expand cycles. A temporary read-only Vite transform
reconstructed the previous TabBar implementation while preserving other local
documentation changes. Each measured endpoint was 44 px collapsed and 288 px
expanded. No phone was accessed.

| Measurement                         | Previous |  Updated |
| ----------------------------------- | -------: | -------: |
| TabBar geometry reads               |    1,005 |       90 |
| Browser layouts                     |      551 |      279 |
| Style recalculations                |      664 |      329 |
| Whole-window frame interval p95     | 149.9 ms |  16.7 ms |
| Whole-window intervals over 33.4 ms |       33 |        6 |
| Maximum whole-window frame interval | 166.7 ms | 116.7 ms |

The updated run's active animation interval p95 was 16.7 ms, with no intervals
over 33.4 ms while moving toward the requested endpoint. This does not establish
real-device frame rate: startup/settlement work still produced a few long frames
in the complete measurement window, and CPU slowdown does not emulate a mobile
GPU. Repeated candidate runs retained 90 geometry reads and 279 layouts; timing
varied. Geometry reads, rather than a machine-specific FPS threshold, are the
automated regression budget (at most 200 across the six transitions).

## Verification

- UI and tokens builds and typechecks; documentation typecheck.
- Affected formatting and lint checks.
- Five TabBar scroll DOM tests, including controlled and uncontrolled state and
  focus behavior.
- Chromium and WebKit mobile navigation checks in light and dark appearance:
  viewport changes, rapid reversals, selected-icon trajectory, native blur during
  resizing, reduced motion enabled mid-animation and expansion focus.
- Chromium and WebKit optical continuity checks at 390 px and 590 px in both
  appearances.
- Chromium and WebKit tablet composition: select the final destination, collapse
  to 44 px, expand to the original width and restore focus to that destination.

Real iPhone smoothness and Safari GPU behavior remain unverified. This work does
not include publication or deployment.
