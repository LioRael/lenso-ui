# 照片拖选与编辑器真机对照

2026-11-06，iPhone 15 Pro Max，iOS 27.2，中文系统照片应用。
通过 iphone-use 实际操作，并对照当前 Chromium 中的 `/en/photos` 与源码。
本次完成研究和可回放检查流程，没有修改 demo 界面或业务实现。

## 多选：已经验证的规则

| 操作                                    | 原生观察                                     | 当前 demo                          |
| --------------------------------------- | -------------------------------------------- | ---------------------------------- |
| 同一行从左向右划过三张                  | 选中三张，底部显示所选内容(3)                | 只有点击，没有拖选处理             |
| 从已选中的该行反向划过                  | 三张均取消选择                               | 没有拖拽取消选择                   |
| 第二行左侧斜向拖至第四行右侧            | 选中连续九张，包含手指没有直接碰到的中间照片 | Shift 连选只能向原选择集合添加范围 |
| 同一次按住拖动，跨行扩选再收回原来一行  | 松手后保留三张，证明区间随端点收缩           | 没有手势会话和初始选择快照         |
| 先横向激活拖选，再停在顶部边缘约 1.8 秒 | 图库自动向较早内容滚动，选择延伸至 35 张     | 没有自动滚动或滚动中的重新命中     |
| 松手、取消                              | 松手保留选择；取消退出并恢复普通工具栏       | 取消已有，拖选缺失                 |

这是按图库顺序扩展的连续区间，不是简单的几何相交选取或逐项 hover 翻转。
从选中项开始反向划过整行可取消该行；混合选中项、锚点跨越和松手中断的
完整规则仍需补测，不能把该单项观察扩大成所有组合均已验证。

首次使用带默认长按的 drag 没有选中；即时 swipe 和 hold_ms=0 的连续路径可以。
这说明实现不应要求先长按才允许划选。精确方向阈值、纯纵向手势仲裁、
触觉反馈、自动滚动速度曲线和帧率尚未量化。

当前缺口位于 `apps/docs/src/components/photos-demo.tsx`：
`toggleSelection`（约 309 行）只有点击翻转与 Shift 范围相加；图库按钮只处理
onClick，没有手势捕获、区间快照、撤回或边缘滚动。

建议实现一个图库选择手势控制器：

1. 每次手势保存锚点、初始选择集合、选择或取消模式。
2. 横向意图明确后接管，保留普通纵向滚动；阈值是待真机对照的 Web 参数。
3. 端点变化时根据初始集合重新计算连续区间，回缩时恢复区间外原状态。
4. 边缘滚动与端点命中使用同一帧循环；即使手指不动，内容移动也继续扩选。
5. 每帧最多提交一次视觉更新，不在每次移动中重测所有照片。
6. 处理快速跨格、丢失指针、第二根手指、筛选或视图切换、松手后的误点击；
   保留现有点击和键盘操作。

这些是后续实施方案，不是已经交付的功能。

## 编辑：已经验证的差异

| 部分     | 原生                                                                            | 当前 demo                                                        |
| -------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 工作区   | 黑色调整/滤镜工作区；裁剪切到深灰并重新安排图片可用空间                         | 一个固定的全屏 Modal 布局                                        |
| 顶部     | 第一排取消/完成；第二排撤销重做、当前模式标题、标记和更多；裁剪时替换成几何工具 | 一排 Cancel / Edit / Done                                        |
| 完成状态 | 未修改时禁用；曝光从 0 调到 68 后按钮变黄并启用                                 | 未修改时也启用黄色 Done                                          |
| 主模式   | 调整、滤镜、裁剪的底部三项玻璃切换                                              | Adjust、Filters 两个文字按钮，裁剪缺失                           |
| 调整工具 | 横向工具带；点击曝光后工具滚到中心；当前名称在上方；非零值进入圆环内            | 三个并排工具，固定文字标签                                       |
| 调整数值 | 中心指示线与移动刻度尺；零点标记；拖动时实时更新图像和圆环数字                  | 普通 Slider 的 Track / Fill / Thumb 与独立数值                   |
| 滤镜     | 连续缩略图带，当前缩略图居中描边；名称在上；选择鲜明后显示强度刻度尺            | Original、Vivid、Mono 三个按钮，没有强度参数                     |
| 裁剪     | 边框和角手柄；翻转、旋转、自动、宽高比；校正/透视工具与刻度尺                   | 全部缺失                                                         |
| 宽高比   | 自由格式、原始比例、正方形、墙纸、16:9 等横向选项；方向切换                     | 全部缺失                                                         |
| 撤销     | 曝光改变后启用撤销；撤销后完成再次禁用，重做启用                                | 只有全局 Reset，没有操作历史                                     |
| 取消     | 有临时裁剪时弹出“确定要放弃更改吗？”与“放弃更改”                                | 立即关闭，未保存状态没有退出确认                                 |
| 图像处理 | 实际观察了曝光、鲜明及裁剪预览；没有保存                                        | CSS brightness/contrast/saturate/grayscale 预览，并栅格化到 JPEG |

原生照片的构图和 demo 素材不同，图片占屏比例不能直接当作同素材像素对比。
但工具栏分区、工具选择器、刻度尺、三模式与状态规则的差异已由实机操作确认。
进场时曾出现临时导航结构后回到裁剪页，尚未确定是模式记忆、素材分析还是
进场时序造成。因此可复用编辑流程从已经稳定的编辑页开始，不猜默认模式。

原生完整参数数量、全部滤镜、滤镜强度具体数值、按住对比的精确行为、裁剪
手柄/缩放/回弹、保存与重开后的非破坏编辑关系，本次没有完整验证。
不能用三种 CSS 函数声称复现了 Apple 的色彩管线。

当前涉及文件：

- `apps/docs/src/components/photos-editor.tsx`：三个参数、两种模式、普通 Slider、无操作历史与退出确认。
- `apps/docs/src/styles/photos-editor.stylex.ts`：固定编辑布局，需要按三种模式重排。
- `apps/docs/src/lib/photos-adjustments.ts`：当前状态只有 exposure/contrast/saturation/preset，没有滤镜强度或几何变换。

建议先重做状态模型和三模式布局，再做工具带与刻度尺：

1. 编辑会话区分进入时的版本与本次草稿，dirty 决定完成与取消行为。
2. 操作历史以完成一次拖动或选择为单位，避免每个刻度变成一次撤销。
3. 各参数独立保留数值，模式切换只换工具，不丢草稿。
4. 参数选择器、刻度尺和底部 Tabs 使用统一的实际状态；原生外观不能把普通
   Slider 换成画出来的无障碍失效控件。
5. 裁剪/旋转/翻转与色彩调整进入同一个非破坏草稿；输出链路需单独验证。
6. 用同一素材比较切换和拖动中间帧，再确认曲线、间距、圆环、文字与材料。

## 保存的检查流程

两段均为本地流程，未发布：

- `photos/drag-selection-reference`：5 步，起点是图库三列竖屏，包含连续路径、回缩、顶部停留；取消选择结束。
- `photos/editor-reference`：17 步，起点是已打开且稳定的未修改静态照片编辑页；查看三模式和宽高比，只旋转临时预览后取消并放弃，返回图库。

两段各完整回放成功一次，并观察到最终普通图库的“选择”按钮。
旧的一体化草稿因滚动位置、素材和进场时序未通过，不安装、不作为验收证据。
这些流程验证可达性和退出路径，不自动验证原生与 Web 的视觉一致性或性能。

所有本次主动修改的编辑草稿均通过撤销或放弃退出，没有按下原生“完成”。
手机已释放控制。通知曾打断一次观察，打断期间的画面不作为参考材料。

## 交付边界

本次交付是研究记录和两段已验证的本地流程；没有实现 demo 的拖选或重构编辑器。
优先顺序：先补可单独验收的拖选控制器，再重构编辑状态和三模式，最后校准视觉动效。
验收必须包含实际拖动路径与中间帧，DOM 测试只能覆盖区间和状态规则。
