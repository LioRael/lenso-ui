# Soft scroll-edge curve refinement

November 8, 2026, Asia/Shanghai. Continues the
[first physical-device calibration](soft-scroll-edge-calibration-2026-11-08.md)
and supersedes its recipe values. This reads and updates the current working
tree; no commit, landing, release or deployment is implied.

The later [top-band refinement](soft-scroll-edge-top-band-2026-11-08.md)
supersedes the recipe values below. This remains the historical second-pass
dataset.

## Result

The same iPhone 15 Pro Max / iOS 27.2 fixture shows lower RGB pixel error on
both the fitting pattern and a held-out public-photo background:

| Dataset                                  | First calibration MAE | Refined MAE | Reduction |
| ---------------------------------------- | --------------------- | ----------- | --------- |
| Pattern, six theme/offset states         | 6.1787                | 3.4122      | 44.8%     |
| Held-out photos, six theme/offset states | 5.5941                | 3.8178      | 31.8%     |

Every one of the twelve states improves. Relative to the original, pre-calibration
pattern error of 16.1184, the refined pattern error is 78.8% lower. These are
fixture-specific encoded-RGB MAEs, not universal native-parity percentages.

## Change

Row-wise mean and contrast measurements separated two residual errors: the
first candidate lost its mid-edge blur too quickly and retained its wash too
long. The top alone was relatively close. An offline Gaussian compositing
model and a fit of the solid-color wash suggested candidate curves; those
predictions were not treated as acceptance. The final numbers above use actual
physical-device screenshots of the candidate.

Six live backdrop filters still use incremental Gaussian variance and raised-cosine
masks. Nominal target radii are now 0.10625, 0.2125, 0.425, 0.85, 1.7 and 3.4 CSS px.
Each mask spans 87.5% of the edge, and successive bands shift by 2.5 percentage
points. This retains more blur through the middle while reducing the peak.
The independent tint mask raises the full-extent cosine to power 1.35, clearing
its middle sooner while retaining zero endpoint slopes. Default tint opacities
are 0.42 light / 0.81 dark over the existing theme color.

Layer count, transparent outer group, scroll visibility binding, directions,
Base UI ownership and opaque accessibility fallbacks remain intact. Explicit
tint/color-opacity overrides remain available; they share the revised tint
falloff. Uniform and hard recipes are unchanged. No consumer prop migration is
required. This is a visual tuning change for soft edges, not a measured frame-rate
or power optimization.

## Measurement

The device, native public UIKit APIs, 96-point bar, shared native label,
automatic-inset correction and three fixed scroll positions remain as in the
first report. Screenshots are 1290 × 2796, with a top-96-point RGB MAE region
of 1290 × 288 pixels. Three offsets (0, 128, 384) are measured in both themes.
The label overlays both native and Web modes. Actual scroll receipts are outside
the measured region. No personal photo content is used.

The pattern uses the original native and calibrated captures, with a fresh
native Y 128 check after the fixture update. Its two checkerboard offsets repeat
the same phase. The photo background is generated by `photo.py` from existing
public docs demo JPEGs, with metadata omitted. It is a six-photo quilt; the
sampled top-edge offsets exercise the first two source photographs, including
different positions within the first. The photo imagery was not used to fit
parameters or to select further candidates after this validation.

The unfiltered y=120–600-point control region has MAE 0.265 or less for every
accepted comparison. The analysis rejects values ≥0.5. One native capture with
a notification banner failed this check and was replaced before the final
analysis; the saved dataset contains the clean replacement.

## Verification and limits

Final package build passed all eight tasks. UI, tokens, testing and the experiment
generator typechecks passed. Eight narrow tests passed: four soft-edge regressions
(302 assertions) and four existing token/theme tests. The new tint regression
catches a slower wash accidentally passing the existing endpoint-only tests.
Changed TypeScript lint/format and source-boundary checks passed.

Actual docs dev review uses Chromium and desktop WebKit at 430 × 900 for the
refined filter values, tint curve/opacity, scrolling, keyboard PageDown, hiding
both edges for short content and increased-contrast layer suppression. Desktop
WebKit's optical limitation described in the first report still applies; the
physical WKWebView captures establish the optical comparison. Photos was also
rendered in both engines in light/dark appearances; its explicit opacity-1
black tint remained, and the revised tint mask was observed in computed styles.

The results remain limited to one device/OS and one bar/label composition.
They do not establish private-shader identity, every content-aware system choice,
larger text, arbitrary toolbar geometries, bottom/horizontal native edges,
RTL optical parity or exhaustive contrast acceptance. Continuous scrolling,
frame rate, energy and high-load behavior were not benchmarked. No full docs
production build or installed-consumer production gate was run for this recipe-only
change. Remaining photo differences show that a single shared curve does not
reproduce every native response.
