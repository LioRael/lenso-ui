# Map one canonical Figma component to each code component

Every code component will have one Canonical Design Component recorded in a versioned Figma-to-code manifest with its file key, node ID, code subpath, supported variants and states, and documentation link. Documentation demos, deprecated sets, and synchronized duplicates are excluded so visual acceptance and implementation ownership remain unambiguous. Figma Code Connect is deferred until the corresponding component API has survived real use; the same manifest remains its future integration source rather than creating a second mapping by hand.
